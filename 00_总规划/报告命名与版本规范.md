# 报告命名与版本规范

生效时间：2026-07-24 16:37（北京时间）

## 一、文件名

统一格式：

```text
YYYY-MM-DD_HHMM_主题域_细分主题_报告类型_v主版本.次版本.md
```

示例：

```text
2026-07-24_1637_AI基础设施_HBM与先进封装_深度报告_v1.0.md
2026-07-24_1637_AI基础设施_高速网络与光互连_深度报告_v1.0.md
2026-07-24_1637_数据中心_供配电与液冷_深度报告_v1.0.md
```

字段解释：

| 字段 | 规则 |
|---|---|
| `YYYY-MM-DD` | 报告生成日期，以北京时间为准 |
| `HHMM` | 首次生成时间，24小时制 |
| `主题域` | AI算力、AI基础设施、半导体、机器人、能源、医疗科技等 |
| `细分主题` | 能够独立理解的具体行业，不使用“专题一”等模糊名称 |
| `报告类型` | 深度报告、更新报告、公司研究、周度复盘、事件快评 |
| `v主.次` | 初版为v1.0；数据/观点补充升次版本，论文重构升主版本 |

## 二、报告头部元数据

每份报告必须包含：

```text
报告编号：
生成时间：
数据截止：
研究状态：
对应主题：
下次复核：
```

报告编号建议使用 `主题缩写-YYYYMMDD-HHMM`。生成时间和数据截止时间不能混用：生成时间说明文件何时创建，数据截止说明信息有效到何时。

## 三、版本规则

- `v1.0`：首次形成完整研究论文。
- `v1.1`：新增数据、财报或小幅调整评分，核心论文不变。
- `v2.0`：核心论文、产业边界或投资结论发生实质变化。
- 旧版本原则上保留；新版本在变更记录中链接旧版本。
- 仅修正错别字或链接时，可原文件修订并记录“非实质修改”。

## 四、索引展示

总索引至少显示：

- 生成时间
- 主题域
- 细分主题
- 类型/版本
- 数据截止
- 核心结论
- 报告链接

索引按生成时间倒序排列，使最新报告始终在最上方。
